Update preview mockups

Ticket #100091 · confirmed by the user ("build it as drawn")

One modal, shown before a downloaded desktop update installs and before the engine updates, lists each ticket the incoming version brings (the ticket number as a link, then its title from the engine's work-item store) under the running → incoming version pair, with Cancel and Update.

  • Desktop update ready: Restart is clicked with a downloaded desktop update. One row per ticket the incoming build brings, its title from the engine's work-item store; a ticket the store does not know reads title unavailable; a PR whose subject names no ticket is a PR #n row.
  • Engine update ready: The lit Update engine is clicked. The header names both builds and how far behind the running one is; the live-run and session lines sit above the list.
  • List missing: The list could not be read in 4 s (the engine did not answer, the build is unstamped, or git log failed). One amber line says why; Update is still offered, because the update never waits on the list.
  • Nothing merged: The two builds are the same commit (a rebuilt image): the list is empty and says so.
